# OctoAcme Project Management Docs

This folder brings together OctoAcme's lightweight, cross-functional project
management guidance. The process emphasizes customer value, iterative delivery,
clear ownership, evidence-informed decisions, and learning in a psychologically
safe environment.

## Project management process

OctoAcme moves work through a simple lifecycle:

1. **Initiate:** Define the problem, intended outcome, success measures, and
   stakeholders in a project one-pager. Confirm alignment and team availability
   before moving into planning.
2. **Plan:** Turn approved work into a prioritized backlog with acceptance
   criteria, estimates, milestones, a Definition of Done, and identified
   dependencies and risks.
3. **Execute and track:** Deliver in small increments using the project board
   and regular standups, delivery syncs, and demos. Keep progress, blockers,
   risks, and outcome metrics visible; escalate issues through the PM, Product
   Lead, and sponsor as needed.
4. **Release:** Verify acceptance criteria, CI and security checks, release
   notes, and rollback plans. Deploy, run smoke tests and post-deployment
   checks, then communicate the release.
5. **Reflect and improve:** After a sprint, release, milestone, or incident,
   capture what went well and what can improve. Assign a small number of
   measurable action items and follow up on them.

Project Managers coordinate delivery, schedules, risks, and communication;
Product Managers define outcomes and priorities; developers and QA deliver and
validate increments; stakeholders provide input and approvals. Regular team and
stakeholder updates, plus a shared source of truth, keep work aligned.
